# shared/

Fixtures that more than one language has to agree with.

Nothing here is source. Everything here was **generated by running the
implementation that owns the behaviour**, and is then read by the tests
of every other implementation. The point is that no single language's
test suite can quietly become the definition of correct.

## consentVectors.json

Owned by `api/_consent.py`. Read by:

- `api/test_consent_vectors.py` — proves the fixture still describes the
  real Python
- `workers/mcp/consent.test.mjs` — proves the JavaScript port agrees

There are two implementations of the consent gate because a Dynamic
Worker's capabilities are composed at the edge (issue #117) and the edge
cannot call Python. Two implementations of a safety decision drift, and
the drift is invisible — both sides keep passing their own tests while
disagreeing about whether somebody's phone rings at 3am.

This file is how that is caught. Change a refusal in either place and
one of the two suites goes red.

### Regenerating

Only after deliberately changing `api/_consent.may_contact`. Never to
make a failing JavaScript test pass — that inverts which side is
authoritative, and the fixture stops being evidence of anything.

```
python3 - <<'PY'
import json, sys, pathlib
sys.path.insert(0, '.')
from api._consent import record, may_contact
# ...build the cases, call may_contact, write the file...
# The generator lives in the commit that introduced this file:
#   git log --diff-filter=A -- shared/consentVectors.json
PY
```

Then run **both** suites and expect them to move together:

```
python3 -m unittest api.test_consent_vectors
npx vitest run workers/mcp/consent.test.mjs
```

If only one moves, one of them is wrong.
